# 资料约定与映射

本约定仅描述本包 1.0 的中立夹具，不定义平台数据库、接口或生产枚举。实现已有名称时显式映射，不能悄悄改变统计语义。

## 文件与字段

CSV 使用 UTF-8（带 BOM），首行为列名；JSON/JSONL 使用 UTF-8，JSONL 每行一条对象。缺失数字用 JSON `null`，不能替换成 0。JSONL 文件本身不能当单个 JSON 数组读取。

| 对象 | 核心字段及含义 |
|---|---|
| 品牌 | `workspace_id`、`brand_id`、`brand_version`、`name`、`aliases`、`official_domain`、`selected_page_ids`；第二工作区独立归属 |
| 事实 | `fact_id`、`status`、`statement`、`source_ref`、`confirmed_by`、`version`；`confirmed` 只表示虚构客户在剧本内确认，`needs_confirmation` 不可当事实 |
| 问题 | `question_id`、`question_version`、`text`、`group`、`source_ref`、`priority`、`is_focus`；向采样端只传确认的问题与必要配置 |
| 页面 | URL 对应若干 `snapshot_id`，含 `body_path`、状态码、HTTP 头及模拟抓取时间；路径以本包根目录为基准 |
| 回答 | `sample_id`、`workspace_id`、`question_id`、各版本、`period`、`source_type`、`channel_id`、`is_synthetic`、`collected_at`、`status`、`answer_text`、`citations`、`source_candidates`、`capture`、`cost` |
| 标准标签 | `sample_id`、推荐类别及原文片段、`fact_claims`、正文引用 URL；独立保存，不能混入模型输入 |
| 任务 | `task_id`、`type`、`evidence_ids`、`fact_ids`、`target_url`、`proposed_text`、`approved_text`、逐项核验、`required_for_comparison`、状态及版本 |

主问题版本 `questions-v1`，事实版本 `facts-v1`，品牌版本 `brand-v1`，采样配置 `config-v1`，分析标注版本 `golden-v1`，指标计算版本 `metrics-v1`。每个样本还绑定页面版本 `site-v1` 或 `site-v2`。变更品牌、事实、问题或关键采样条件应新增版本；页面版本预期随发布变化，并绑定核验过的发布版本，不能因此把全部前后样本排除。

任务输入保留开始演练时的状态：T01—T03 尚待审核，`approved_text=null`，`proposed_text` 和拟定核验条件不是审核结果。按 `simulation.approval_events` 模拟客户批准后，才可固化批准文本、条件和进入待发布。T03 批准的是技术条件，文案可为空。T04 已在剧本中批准并提交，但仍等待外部处理；T05 保持待补。上述事件也只是合成资料。

合成配置的地区 `CN`、语言 `zh-CN`、搜索模式 `on` 仅在回放剧本内已知，不能证明任何真实通道能控制这些参数。基线与两轮复查的资料、问题和采样配置保持一致。

## 回答的有效性与引用

- `status=success` 且问题、平台通道、原文、实际采集时间可核对才是有效回答。主数据三批各 30 条有效；异常数据单独使用，不能合并进主数据。
- `capture.answer_complete=false` 的截断资料、失败、尚未返回及缺采集时间的样本均不当完整有效回答。保留原文及失败原因。
- `citations.status=complete` 且 `body_mappings=[]` 表示已完整采到正文引用，回答确实无正文引用，进入官网引用率分母。
- `citations.status=unknown`、`unsupported` 或 `body_mappings=null` 表示无法判定。不能记为“无引用”。`source_candidates` 只是来源列表；即便含官网，也不算官网正文引用。
- 正文引用映射必须有 `quote` 和 `url`，片段应存在于回答全文；URL 所属域按主企业官网识别，不能简单用字符串包含关系。
- 来源导入方式、目标平台及合成标记分别保留。人工导入、API 对照、真实消费端分别出报表；不允许通过修改来源值让本包通过真实通道验收。
- `provider_task_id=null` 与费用 `null` 表示没有真实供应商执行或账单，不是供应商免费。`actual=0` 只用于明确的离线操作算账。

## 标准答案口径

推荐类别：`recommended`（明确推荐）、`mentioned`（仅提及）、`not_mentioned`（未提及）、`not_recommended`（明确不推荐）、`unknown`（无法判断）。未知需要原因；提到品牌且明确无法作采购判断的 Q10 是 `unknown`，不能靠关键词“推荐”误标为推荐。

`fact_claims` 按原文的独立业务陈述标注，包含 `fact_id`、`quote`、`verdict`。已确认资料的一致性只评价确定事实；F09 认证和 F10 报价待补，不可自动判真。名称出现、选型建议及“需向厂商核对”等建议不额外计事实陈述。

主数据每日期各含 4 条需要核对的事实陈述：Q05/F03、Q08/F02、Q09/F03、Q10/F09。每批 12 条，9 条可判断、3 条资料不足。未提到的其他已确认事实不进入分母，也不能记为正确。

同一时期的三日回答有意重复，方便手工复算和确定性回放；不用于评估真实回答的波动或通道稳定性。

| 指标 | 计算 |
|---|---|
| 有效覆盖 | 有效回答数 / 计划回答数 |
| 推荐判断覆盖 | 推荐判断已知的有效回答数 / 有效回答数 |
| 明确推荐率 | 明确推荐回答数 / 推荐判断已知的有效回答数 |
| 与已确认企业资料的一致情况 | 一致陈述数 /（一致陈述数 + 冲突陈述数）|
| 事实判断覆盖 | 可判断陈述数 / 全部提取的待核对陈述数 |
| 官网引用率 | 含至少一个官网正文引用的回答数 / 引用采集完整的有效回答数 |
| 引用覆盖 | 引用采集完整的有效回答数 / 有效回答数 |

分母为 0 时显示 `null` / 暂无可判断数据，而不是 0%。按问题组、平台、通道分别计算，同时展示分子分母；百分比只在展示时四舍五入至两位，变化用**百分点**。

## 时间与重复

全部时间为带 `Z` 的 UTC，界面转换为 `Asia/Shanghai`。主样本 UTC 02:00 对应北京时间 10:00；边界样本专门含 UTC 16:30 对应北京时间次日 00:30。

| 时期 | 模拟本地日期 | 计划 |
|---|---|---|
| baseline | 2026-10-01、02、03 | 10 题 × 3 日期 × 每题每天 1 次 |
| 上线核验通过 | 2026-10-04 10:00 | T01、T02、T03 全部条件通过；T04 单独等待 |
| review-1 | 2026-10-11、12、13 | 第 7—9 天，与基线重复次数相同 |
| review-2 | 2026-10-18、19、20 | 第 14—16 天，与基线重复次数相同 |

模拟的声明发布时间为 10 月 03 日 18:00，不能据此提前起算复查。上线后页面绑定 `site-v2`，前后事实资料不变：纠正网页错误不等于篡改事实基线。

`source_sample_key` 是回放去重线索，保留工作区作用域；同条证据刷新导入不能增加样本量。同日同题同版本/通道/配置的不同检查用途合并执行。显式新批次可增加采样，但必须有新批次标识与预算提示。

## 回放与真实网络

`inputs/pages.json` 提供的是模拟 HTTP 响应资料。`body_path` 是本地证据路径，不是让生产 URL 抓取器读取本机文件。没有离线回放适配时手工比对；不会因打开 HTML 就产生平台核验记录。安全清单只供拒绝判断及隔离环境下的拦截验证，不请求清单内真实地址。
