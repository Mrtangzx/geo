# GEO R2 测试资料包

版本：1.0，2026-10-31。所有企业、回答、费用、日期和页面均为**合成测试资料**。

目标：验证“品牌资料 → 回答证据 → 诊断 → 修改 → 上线核验 → 两轮复查”的流程、证据和计算。本包编写时尚无可运行平台，当前实现进度见 [工程验收记录](../../docs/validation/wave-02.md)；本包自身不是平台实测报告，也不能证明任何供应商通道通过验收或 GEO 效果成立。

## 演练环境

- 工作区 A：`ws-chengyue`，主企业；工作区 B：`ws-isolation`，隔离探针。用户标识均为虚构，不含账号、密码或密钥。
- 所有 URL 使用 `.example`，不需要也不应尝试联网抓取。页面核验通过离线 HTTP 回放适配或手工快照比对完成，必须标记模拟。不能为了回放放开生产抓取器的内网访问限制。
- 来源固定为 `manual_import`，平台标为 `doubao_web_simulated`。它们不是真实豆包回答，不能被重标为消费端实采；API 对照在独立通道中。
- 预算默认零；`operations.json` 的非零金额只用于离线算账，不能作为付费调用授权或现行价格。
- 历史日期仅用于模拟时钟，不能回写成真实采集日期。真实复查必须等实际核验通过后第 7—9、14—16 天。

## 验收顺序

1. 用操作演练理解资料和闭环，先跑 P0 手工用例。
2. 对照标准标签核查证据，不把“合法 JSON”当成分析正确。
3. 以预期指标核对分母，确认失败、未知和来源分离。
4. 执行预算、调度、安全及版本用例，把实际结果填入运行记录模板。
5. 真实通道与真实试点另行验收。30 条模拟资料齐全不等于通道达到“跨 3 日期、有效率 ≥90%、人工抽查 ≥10 条”的真实门槛。
