## 本轮实际检查

已阅读当前官方 DataForSEO 提交/查询/错误码与条款、百炼原生API/搜索/目标模型文档，入口和实现边界见 [外部通道说明](../channels.md)。供应商账号、商用用途、当期价格与真实模型可用性仍待核对。

在本地通过一次性命令直接调用纯函数并人工核对输出，未调用网络：

| 场景 | 实际结果 |
|---|---|
| 问题含中文、`+`和`%` | 请求字段解码后与原问题完全一致，没有附加品牌词 |
| DataForSEO `20100` + 唯一任务ID | 标记accepted，保存原任务ID与原POST费用 |
| 官方样例中非RFC版本/variant的任务ID | 按供应商8-4-4-4-12十六进制格式接受，查询路径保留原ID；不误用内部严格UUID规则 |
| `50000`且费用缺失 | 标记unknown，费用null，不证明免扣费 |
| `40501`且本任务费用明确0 | 标记not_accepted；没有将模糊响应当作免扣费 |
| `40602`原ID查询 | 保持pending |
| 完整结果含来源列表 | 原文、供应商时间、语言/位置保存；正文引用保持unknown/null |
| 查询返回其他任务ID | unavailable，不保存为当前证据 |
| 千问原生搜索请求 | 请求同一原问题，enable_search=true，来源/角标单独请求 |
| 千问响应缺搜索信息/返回模型 | 搜索实际状态和返回模型均null，不用请求值补写 |
| `finish_reason=length` | 原文保留但answerComplete=false |
| 分析请求 | enable_search=false，没有tools，使用当前项目事实和证据，不含golden |
| 缺密钥和可靠费用上限 | configured=false，paidCallsEnabled=false，acceptance=not_verified |

首次全项目类型检查与适配文件ESLint检查通过。随后UI正并行整合，复验全项目曾出现`SamplingView`导出及面板props的未完成整合错误，适配文件ESLint仍通过；最终全项目检查由根代理整合后重跑。上述数据是本地人工构造的契约输入，不是供应商实测响应或通道质量证明。
