# #16 邀请登录与工作区隔离：服务验证

日期：2026-10-31。验证环境为 Windows 本机、真实 PostgreSQL 17.11，所有账号和品牌均为合成资料。

## 实现与范围

- Better Auth 1.7.14、同版本 Drizzle adapter；真实邮箱密码登录、数据库会话及退出。
- 原始开放注册关闭。CLI 生成48字节随机邀请，数据库仅存 SHA-256 哈希；接受邀请时事务锁定、消费并创建账号及成员关系。
- 默认新工作区；明确指定既有工作区才授予既有数据访问。全部现有业务路由通过异步 `getLocalContext()` 解析真实会话与 membership。
- 使用独立 `127.0.0.1:3001` 邀请模式服务，构建目录 `.next-invite`；主工作区的本地模式环境文件未切换。
- 私有验收配置、邀请与账号凭据均保存在被忽略的 `.local/` 中，本记录不包含密码、邀请原文或 cookie。

## 实际结果

| 场景 | 结果 |
|---|---|
| 匿名读取会话 | 200，invite、user/workspace=null、needsLogin=true |
| 匿名访问项目 | 401 |
| 直接调用开放注册入口 | 403，不能绕过邀请 |
| 两个不同邮箱的默认邀请 | 分别建立两个不同的新工作区 |
| 接受两个有效邀请 | 各201 |
| Better Auth 登录 | 各200，实际下发会话 cookie |
| 两账号创建与列出项目 | 各自工作区各1个合成项目，响应归属正确 |
| 跨工作区项目详情、版本读取 | 各404；己方版本读取200 |
| 跨工作区项目修改 | 404 |
| 客户端通过 query/header 指定另一工作区 | 仍只返回会话所属工作区的数据 |
| 会话状态 | 依据真实会员关系返回正确工作区 |
| 重放已用邀请 | 400 |
| 有效邀请与错误邮箱 | 400 |
| 同一全新邀请并发接受 | 一次201、一次400 |
| 过期邀请 | 400，确认未创建该账号 |
| 跨 Origin 接受邀请 | 403 |
| Better Auth 退出 | 200，随后访问项目401 |
| 问题、问题版本列表 | 己方200、另一工作区404 |
| 页面及页面版本列表 | 己方200、另一工作区404 |
| 已存在页面快照详情 | 己方200、另一工作区404 |
| 显式指定 local-workspace 的邀请 | 接受201，登录后工作区为 local-workspace，可读取其现有3个项目 |
| 邀请模式缺少密钥 | 配置解析实际抛出503/AUTH_NOT_CONFIGURED，不回退本地身份 |
| 登录页面服务响应 | 200；完整浏览器交互由主代理统一验收 |

实际会话 cookie 验证 HttpOnly=true。本机 HTTP 的 Secure=false，外部 HTTPS 使用 Secure 的配置已实现；本轮未部署真实 HTTPS，不把配置检查作为真实 TLS 验收。

原子邀请验证使用全新合成邮箱；一次性和过期结果均来自实际数据库与 HTTP 操作。页面快照访问验证证明存取授权，不据此宣称页面采集质量或 AI 收录已验收。

## 依赖审计记录

`npm audit --omit=dev --registry=https://registry.npmjs.org` 返回4项 moderate，0 high、0 critical。四项均来自同一传递链：`drizzle-kit@0.31.11 → @esbuild-kit/esm-loader → @esbuild-kit/core-utils → esbuild`。

根项目将 drizzle-kit 声明为开发依赖，但 `better-auth@1.7.14` 同时声明其可选 peer，npm 实际依赖图将其标为 `dev=false`；因此它仍出现在 omit-dev 审计中，不能写成“生产依赖零漏洞”。本项目用该工具链处理迁移生成，未启动 esbuild serve。

对应 [GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99) 涉及旧版 esbuild 开发服务的跨站读取，修复版本为0.25.0起。npm 自动建议降级 drizzle-kit 到0.18.1，不适合作为当前迁移工具的直接修复。本轮未 force 降级、未把工具链重构混入认证实现；最终对外部署前继续核对并处理该传递依赖。
